## Webhooks Overview

Webhooks in Qwin Q Documentation allow you to receive real-time notifications about events in your documentation space. Automate workflows by integrating with external services and tools.

<Callout kind="info">Webhooks deliver JSON payloads to configured endpoints when specific events occur.</Callout>

## Setting Up Webhooks

Create and configure webhooks through the admin dashboard.

<Steps>
  <Step title="Access Webhook Settings" icon="settings">
    Navigate to Settings > Integrations > Webhooks.
    
    You'll see a list of existing webhooks and options to create new ones.
  </Step>
  <Step title="Create New Webhook" icon="plus">
    Click "Add Webhook" and configure the endpoint.
    
    <ParamField body="url" param-type="string" required="true">
      The endpoint URL where webhook payloads will be sent.
    </ParamField>
    
    <ParamField body="secret" param-type="string" required="false">
      Optional secret for payload verification.
    </ParamField>
  </Step>
  <Step title="Select Events" icon="bell">
    Choose which events should trigger the webhook.
    
    <Expandable title="Available Events" default-open="false">
      - Document created
      - Document updated
      - Document deleted
      - User added
      - Project published
      - Comment added
    </Expandable>
  </Step>
  <Step title="Test and Activate" icon="play">
    Send a test payload and enable the webhook.
    
    Verify the endpoint receives and processes the payload correctly.
  </Step>
</Steps>

## Security and Verification

Secure your webhooks with signature verification.

<Callout kind="alert">Always verify webhook signatures to prevent unauthorized requests.</Callout>

<Steps>
  <Step title="Generate Secret" icon="key">
    Create a secret key when setting up the webhook.
    
    Store this secret securely - it won't be shown again.
  </Step>
  <Step title="Verify Signature" icon="shield">
    Check the X-QwinQ-Signature header in requests.
    
    <CodeGroup tabs="Node.js,Python">
      ```javascript
const crypto = require('crypto');

function verifySignature(payload, signature, secret) {
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(signature, 'hex'),
    Buffer.from(expectedSignature, 'hex')
  );
}
```
      ```python
import hmac
import hashlib

def verify_signature(payload, signature, secret):
    expected = hmac.new(
        secret.encode(),
        payload.encode(),
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature, expected)
```
    </CodeGroup>
  </Step>
</Steps>

## Retry Logic

Qwin Q Documentation automatically retries failed webhook deliveries.

<Expandable title="Retry Policy" default-open="false">
  - Initial attempt immediately
  - Retry after 1 minute
  - Retry after 5 minutes
  - Retry after 30 minutes
  - Final retry after 2 hours
  - Total of 5 attempts
</Expandable>

### Slack Integration

<CodeGroup tabs="Webhook Script,Slack App">
  ```javascript
// Express.js webhook handler for Slack
app.post('/webhook/qwinq', (req, res) => {
  const payload = req.body;
  
  // Send to Slack
  fetch(process.env.SLACK_WEBHOOK_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      text: `Document ${payload.event}: ${payload.data.title}`,
      attachments: [{
        fields: [
          { title: 'Project', value: payload.data.project_name },
          { title: 'User', value: payload.data.user_name }
        ]
      }]
    })
  });
  
  res.sendStatus(200);
});
```
  ```bash
# Using Slack's incoming webhooks
curl -X POST https://hooks.slack.com/services/... \
  -H "Content-Type: application/json" \
  -d '{"text":"Documentation updated!"}'
```
</CodeGroup>

## Troubleshooting

Common webhook issues and solutions.

<ExpandableGroup>
  <Expandable title="Webhook Not Firing" default-open="false">
    - Check event selection in webhook configuration
    - Verify the webhook is active
    - Review server logs for errors
  </Expandable>
  <Expandable title="Invalid Signature" default-open="false">
    - Ensure secret matches between Qwin Q and your endpoint
    - Check payload encoding (should be UTF-8)
    - Verify HMAC algorithm (SHA-256)
  </Expandable>
  <Expandable title="Timeout Errors" default-open="false">
    - Ensure endpoint responds within 10 seconds
    - Check for network issues
    - Implement asynchronous processing for long-running tasks
  </Expandable>
</ExpandableGroup>

## Best Practices

<Callout kind="success">Follow these guidelines for reliable webhook implementations.</Callout>

- Use HTTPS endpoints for security
- Implement idempotency to handle duplicate deliveries
- Process webhooks asynchronously
- Validate payloads before processing
- Monitor delivery success rates
- Have fallback mechanisms for critical notifications

Webhooks provide powerful automation capabilities, allowing you to integrate Qwin Q Documentation seamlessly into your existing workflows and notification systems.
